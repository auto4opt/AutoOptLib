# Public API

Import the supported interfaces from `autooptlib`.

## Problem definition

`make_problem(objective, bounds=..., constraint=..., data_factory=...)` wraps
an objective to minimize. The objective receives `(decision, instance_data)`
and returns a finite scalar. Positive constraint values denote violations.
See [custom problems](custom-problems.md).

## Algorithm design and execution

`autoopt(**options)` returns `(algorithms, trace)` in design mode and
`(best_solutions, histories)` in solve mode. Keyword spellings are
case-insensitive and underscore-insensitive; unknown options are rejected.

| Option | Purpose |
| --- | --- |
| `Mode` | `design` or `solve` |
| `Problem` | Callable problem definition |
| `InstanceTrain`, `InstanceTest` | Training and held-out instance identifiers |
| `InstanceSolve` | Instance identifiers to solve |
| `DesignSpace` | Permitted operators, parameters and structures |
| `Algorithm` | An `AlgorithmGraph` or decoded `Design` to execute |
| `AlgFile` | Saved algorithm JSON to execute |
| `AlgName` | Built-in convenience algorithm preset |
| `ProbN` | Population size when not specified by the algorithm |
| `ProbFE` | Objective-evaluation limit per algorithm run, including initialization |
| `AlgN` | Number of final algorithms retained |
| `AlgFE` | Candidate-proposal limit, excluding initialization and held-out evaluation |
| `DesignFEs` | Optional total training evaluation cap, including initialization |
| `AlgRuns` | Repeated runs per instance |
| `Seed` | Random seed |
| `OutputDir` | Directory for output files generated by this call |
| `ComponentBackend` | `python` or `native` |
| `StreamBackend` | Use `batch` with the native engine |
| `EvalWorkers` | Evaluation worker count, default 1 |
| `CheckpointDir`, `Resume` | Save and resume compatible design/solve checkpoints |

The design method is Search (`Designer="search"`). Random-design comparison
entry points are not part of the public library. Operator choice, combination,
structure and parameter search remain in the Search engine.

The graph model provides `Operator`, `Stage`, `Pathway`, `AlgorithmGraph`,
`NodeSpace` and `DesignSpace`. See the
[programming model](graph-programming-model.md) for the supported grammar.

## Discovery and extensions

- `list_components()` lists built-ins and registered extensions.
- `describe_component(name)` describes an operator and its execution support.
- `get_component_contract(name, problem=None)` returns its typed contract.
- `register_operator(...)` registers a `ComponentRequest -> ComponentResult`
  implementation with parameter, data-flow and backend requirements.
- `register_component(...)` supports the lower-level callable interface.

Custom components must be registered before loading algorithms that reference
them. Python components are not automatically compiled into native kernels.

## Algorithm persistence

`save_algorithm(design, path)` and `load_algorithm(path)` write and validate
portable JSON. `algorithm_to_dict` and `algorithm_from_dict` provide in-memory
forms. Saved designs include execution semantics; incompatible backend requests
are rejected. Use `AlgorithmGraph.from_design(design)` to inspect a design.

`AlgName` presets are convenience combinations of this library's operators,
not external competitor implementations or paper experiment configurations.
